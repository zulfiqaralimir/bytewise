# 2.1: Recurrence Relation $T(n) = T(n-1) + 1$ — Part 1

*Based on [Abdul Bari's Algorithms playlist](https://youtu.be/0IAPZzGSbME?si=yLoAVtKfYvm_5b8K).*

---

## The Example Algorithm

To learn how to trace a recursive function, write its recurrence relation, and solve that relation, we start with one simple recursive C function:

```c
void Test(int n)
{
    if (n > 0)
    {
        printf("%d", n);
        Test(n - 1);
    }
}
```

- **What it does:** given `n`, if `n > 0` it prints `n`, then calls itself with `n - 1`.
- If `n` is not greater than `0`, the function does nothing further — it simply returns.

---

## Tracing the Recursion: Test(3)

Let's trace what happens when we call `Test(3)`, step by step:

1. `Test(3)`: since `3 > 0`, print **3**, then call `Test(2)`.
2. `Test(2)`: since `2 > 0`, print **2**, then call `Test(1)`.
3. `Test(1)`: since `1 > 0`, print **1**, then call `Test(0)`.
4. `Test(0)`: since `0` is **not** greater than `0`, the condition fails — no further call is made, and the recursion stops.

This chain of calls is often called a **tracing tree** or **recursive tree** — even though here, since each call makes exactly one recursive call, it's a simple straight line rather than a branching tree.

---

## Counting the Work

- The main work done in each call is the **print statement** — everything else (the condition check, the call itself) is treated as constant overhead.
- Each print costs **one unit of time.**
- For input `n = 3`:
  - **Prints executed:** 3 times (for `n = 3, 2, 1`).
  - **Total calls made:** 4 — that is, `3 + 1` (the `+1` accounts for the final call, `Test(0)`, which makes no further call but is still a call).
- **Generalizing to any n:**
  - Total calls made = **n + 1**
  - Total prints executed = **n**
- If we approximate the total work as proportional to the number of calls, the time function is $f(n) = n + 1$, which is $\Theta(n)$ — written equivalently as $O(n)$ or $\Omega(n)$.

> This is the **tracing-tree method** of finding time complexity: draw out the calls, count them, and read off the growth rate. Next, we'll find the *same* answer using a more formal tool — the **recurrence relation.**

---

## From Code to Recurrence Relation

- By convention, the time-taken function is named $T(n)$ (rather than $f(n)$).
- To build the recurrence, look at what happens **inside one call** of `Test(n)`:
  - The `if` condition check is ignored (or folded into a constant) — it doesn't change the growth rate.
  - The `printf` statement is a single, simple statement → costs **1** unit of time.
  - The recursive call `Test(n - 1)` costs whatever `Test` costs for input `n - 1` → that is, $T(n-1)$.

Adding these pieces together:

$$T(n) = T(n-1) + 1$$

> **Why fold the condition check into the constant?** If we counted the `if` check as its own unit, we would get $T(n) = T(n-1) + 2$ instead. The two versions differ only by a constant factor, and solving either one gives the **same order of growth.** Any constant amount of per-call work can be written as `1` (or generically as `c` or `a`) without changing the final complexity class — so we simply choose `1` for simplicity.

---

## The Full Recurrence Relation

A recurrence relation isn't complete without a **base case** — what happens when `n = 0`. Even though the function does nothing when `n = 0`, we still record a **constant** cost (not zero), since checking the condition and returning still takes some fixed amount of time:

$$
T(n) =
\begin{cases}
1 & n = 0 \\
T(n-1) + 1 & n > 0
\end{cases}
$$

---

## Solving by the Substitution Method

We now solve $T(n) = T(n-1) + 1$ by repeatedly substituting the recurrence into itself:

1. Start with the relation itself:
   $$T(n) = T(n-1) + 1 \quad \text{...(i)}$$

2. Since the relation holds for **every** value of $n$, it also holds one step earlier — replace $n$ with $n-1$:
   $$T(n-1) = T(n-2) + 1$$

3. Substitute this into (i), in place of $T(n-1)$:
   $$T(n) = \big[T(n-2) + 1\big] + 1 = T(n-2) + 2$$

4. Repeat the same step — replace $n-1$ with $n-2$ to get $T(n-2) = T(n-3) + 1$, and substitute again:
   $$T(n) = \big[T(n-3) + 1\big] + 2 = T(n-3) + 3$$

5. A clear pattern has emerged. Continuing this process for **$k$ substitutions**:
   $$T(n) = T(n-k) + k$$

---

## Reaching the Base Case

The substitutions should stop exactly when we reach the known base case, $T(0) = 1$. So we choose $k$ such that:

1. Assume the subtraction has reached zero:
   $$n - k = 0 \quad \implies \quad n = k$$

2. Substitute $k = n$ into $T(n) = T(n-k) + k$:
   $$T(n) = T(n-n) + n = T(0) + n$$

3. We know the base case: $T(0) = 1$. Substituting:
   $$T(n) = 1 + n$$

---

## Final Result

$$T(n) = n + 1 \;=\; \Theta(n)$$

- This matches **exactly** what the tracing tree gave us above — `n + 1` total calls.
- Both methods — the informal tracing tree and the formal recurrence relation — arrive at the **same growth class: linear, $\Theta(n)$.**

---

## The Big Picture

- A recursive function's cost can be found two ways: **tracing the recursion tree** (informal, visual) or **writing and solving a recurrence relation** (formal, algebraic) — both should agree.
- To build a recurrence: constant statements contribute **1** (or a constant `c`); each recursive call contributes its own $T(\cdot)$ term.
- A recurrence relation needs a **base case** (e.g., $T(0) = 1$) and a **recursive case** (e.g., $T(n) = T(n-1)+1$ for $n>0$).
- The **substitution (back-substitution) method** solves a recurrence by repeatedly expanding $T(n-1)$, $T(n-2)$, ... until a clear pattern $T(n) = T(n-k) + k$ appears.
- Setting $n - k = 0$ (i.e., $k = n$) plugs in the base case and yields the closed-form answer.
- For this recurrence: $T(n) = n + 1$, which is $\Theta(n)$ — a **linear** time algorithm.

> **Simple takeaway:** every recurrence relation is just the code talking — constant lines contribute a constant, the recursive call contributes itself one step smaller — and substitution is nothing more than unwinding that call chain algebraically until you hit the base case.
