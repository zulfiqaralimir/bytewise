# 6.1: The N-Queens Problem — Backtracking

---

## 1. What Is the N-Queens Problem?

Picture a chessboard. A standard board is 8×8, but to keep things manageable while we learn the technique, we'll shrink it down to a **4×4 board with 4 queens**.

In chess, a queen can move **horizontally** (along its row), **vertically** (along its column), or **diagonally** — in any of those directions, for any distance. Two queens are said to be **under attack** if they share:

- The **same row**, or
- The **same column**, or
- The **same diagonal**

The N-Queens problem asks: can you place all N queens on an N×N board so that **no two queens attack each other**?

For 4 queens on a 4×4 board, the answer is yes — and in fact there's more than one way to do it. That last point matters a lot for how we approach the problem.

**Why backtracking, and not dynamic programming?** Dynamic programming is the right tool when you want a single *optimal* answer. Here, we don't want just one arrangement — we want **every valid arrangement** that satisfies the no-attack condition. Whenever a problem asks for *all* solutions meeting some condition (rather than the *one best* solution), that's a strong signal to reach for **backtracking**.

---

## 2. Reducing the Size of the Problem

Before diving into backtracking, it's worth noticing just how large the raw search space is — and how a couple of smart observations shrink it dramatically.

**The naive count:** with 16 cells on a 4×4 board and 4 queens to place, you could naively try every possible group of 4 cells: `16C4` combinations. That's already a lot, and it only gets worse as the board grows.

**Observation 1 — one queen per row.** Since no two queens can share a row anyway, there's no reason to ever consider placing two queens in the same row. So instead of choosing 4 cells out of 16 freely, we can simply decide: *the first queen goes somewhere in row 1, the second in row 2, the third in row 3, the fourth in row 4.* Each queen "owns" a row.

This reframes the whole problem. We no longer need to track *which cell* each queen sits on — we only need to track **which column** it occupies within its row.

**Observation 2 — one queen per column too.** Similarly, no two queens can share a column, so we can also avoid ever placing two queens in the same column while building up our arrangement.

**The result:** the problem reduces to filling an array `X[1..4]`, where `X[i]` holds the column number of the queen placed in row `i`. Row and column conflicts are handled automatically by this setup — the only thing left to check is **diagonal conflicts**.

## 3. Building a State Space Tree (Without Checking Diagonals Yet)

To organize the search, we build a **state space tree** — a tree where each level corresponds to one row, and each branch represents a choice of column for the queen in that row.

Let's first build this tree *without* worrying about diagonal attacks at all, just to see how large the raw search space is once row and column conflicts are already ruled out.

- At the root, we haven't placed any queens yet.
- **Level 1** (row 1): the first queen can go into any of the 4 columns → **4 branches**.
- **Level 2** (row 2): whichever column the first queen took is now unavailable, so the second queen has **3 remaining choices**.
- **Level 3** (row 3): two columns are now taken, leaving **2 choices**.
- **Level 4** (row 4): three columns are taken, leaving exactly **1 choice**.

**Counting the nodes:** at each level, the number of nodes is the product of the choices available so far. Summing across all levels (plus the root itself) gives:

$$\text{Total nodes} = 1 + \sum_{i=0}^{3} \prod_{j=0}^{i} (4-j) = 1 + 4 + (4\times3) + (4\times3\times2) + (4\times3\times2\times1) = 65$$

**In general, for N queens:**

$$\text{Total nodes} = 1 + \sum_{i=0}^{N-1} \prod_{j=0}^{i} (N-j)$$

This is the **maximum** number of nodes we'd ever need to generate — the actual number explored during backtracking will typically be much smaller, since we'll be cutting off (pruning) branches the moment they violate a constraint, rather than generating them in full and checking afterward.

## 4. Applying the Bounding Function

Now we bring diagonals into the picture. The **bounding function** is simply the full condition we check before extending any branch of the tree: *the new queen must not share a row, a column, or a diagonal with any queen already placed.*

The key idea of backtracking: as soon as a placement violates this condition, we **stop immediately** — we don't bother exploring anything further down that branch. We mark that node as a dead end and backtrack to try the next possibility at the previous level. This is what makes backtracking so much more efficient than generating the entire raw tree from Section 3 and checking it afterward.

Let's trace through the process for our 4-queens example, following exactly how the search unfolds.

### Branch 1: X₁ = 1 (placing the first queen in column 1)

- **X₂ = 2** → under diagonal attack from X₁ → **dead end**, backtrack.
- **X₂ = 3** → not under attack, continue.
  - **X₃ = 2** → under diagonal attack → dead end.
  - **X₃ = 4** → under diagonal attack → dead end.
  - No valid column remains for the third queen → backtrack to X₂.
- **X₂ = 4** → not under attack, continue.
  - **X₃ = 2** → not under attack, continue.
    - **X₄ = 3** (the only remaining column) → under diagonal attack → dead end.
  - **X₃ = 3** → under diagonal attack → dead end.
  - No valid column remains for the third queen → backtrack to X₂.
- No columns remain for X₂ → **backtrack all the way to the root.** The entire X₁ = 1 branch produces no solutions.

### Branch 2: X₁ = 2 (placing the first queen in column 2)

- **X₂ = 1** → under diagonal attack → dead end.
- **X₂ = 3** → under diagonal attack → dead end.
- **X₂ = 4** → not under attack, continue.
  - **X₃ = 1** → not under attack, continue.
    - **X₄ = 3** (the only remaining column) → not under attack → **a full, valid arrangement!**

This gives us our first solution: **X = (2, 4, 1, 3)**.

### The Remaining Branches

Continuing the search past this first solution, the algorithm backtracks and tries **X₁ = 3**. This branch turns out to be the **mirror image** of the X₁ = 2 branch (reflected across the middle of the board) and produces a second solution: **X = (3, 1, 4, 2)**.

Finally, **X₁ = 4** mirrors the X₁ = 1 branch and, like it, produces no solutions at all.

---

## 5. The Final Solutions

Putting it all together, the 4-queens problem has exactly **two solutions**:

- **X = (2, 4, 1, 3)**
- **X = (3, 1, 4, 2)**

These two solutions are mirror images of each other across the vertical centre of the board — which makes sense, since the whole problem is symmetric left-to-right.

**Key takeaway:** backtracking works by building the state space tree *incrementally*, checking the bounding function (row, column, and diagonal conditions) at every single step, and immediately abandoning any branch that fails. This lets us find *all* valid solutions without ever having to fully construct — or fully check — the much larger raw tree of 65 possibilities we counted back in Section 3.
