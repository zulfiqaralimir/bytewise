# Claude Code and OpenCode: A Crash Course

*15 Concepts · 80% of Real Use*

## Summary

- **Think of this as:** a crash course on two tools, Claude Code and OpenCode, that don't just chat about your files — they open them, edit them, and save the result while you watch.
- **The point of it:** by the end, you'll have moved from "AI gives me advice" to "AI does the work correctly" — and you'll know exactly how much to trust it.
- **Where it applies:** anywhere your work lives in files — spreadsheets, scripts, reports, repetitive computer tasks. You don't need to be an engineer for this to be useful.
- **Why this matters if you're in Investment work:**
  - The boring, repetitive stuff stops being something you do by hand every single time. Example: a quarterly DCF model needs the latest earnings numbers dropped in and every downstream cell recalculated — the agent opens the model, updates the assumptions tab, and flags anything that moved more than 10%, instead of you doing it line by line.
  - Point an agent at a valuation model or a tracker, and it can pull the data, run the numbers, and update the file directly, right there. Example: reconciling a broker statement against your internal position ledger — the agent reads both files, matches trades, and lists only the mismatches instead of you eyeballing two spreadsheets.
  - You can build small internal tools — screeners, dashboards, one-off analysis scripts — without waiting on an engineer to have time for you. Example: "screen this list of 200 tickers for P/E under 15, revenue growth over 10%, and debt-to-equity under 1" — the agent writes and runs the script, hands you the filtered list.
  - Turning a raw spreadsheet into a formatted investor memo or IC (investment committee) note — the agent restructures the numbers into prose and tables, you review the judgment calls.
  - The core skill you're about to learn, **context engineering**, is exactly what keeps AI-run financial work accurate instead of made up. Feed it the right numbers and rules, nothing more, nothing less, and it stays honest.

## What These Tools Actually Do

- Picture this: you've got an essay draft. The grammar's rough, the paragraphs are in the wrong order.
- You tell your computer: fix the grammar, reorder the paragraphs so the argument flows, save the new version.
- Here's the difference — it doesn't hand you a list of suggestions. It opens the file, makes the edits, and saves the result, right in front of you.
- That's the whole idea behind Claude Code and OpenCode. You describe what you want, they actually do it, and you review the result.

## The One Idea Behind Everything

- Here's the key insight: almost every "advanced" trick in these tools boils down to one move — **giving the AI the right information at the right time, and keeping the irrelevant stuff out.**
- Every section in this course loops back to that same idea, one way or another.
- The industry has a name for it: **context engineering** — deliberately deciding what the model gets to see.

- **What the picture shows:** four layers, nested inside each other, each one wrapping the layer before it.
  - **Layer 1 — The Prompt:** what you actually type or say.
  - **Layer 2 — The Context:** what the model gets to see — this is the layer this course lives in.
  - **Layer 3 — The Harness:** what the surrounding system enforces around the model.
  - **Layer 4 — The Loop:** what keeps running on its own, without you sitting there.
  - Off to the side, a separate check: **did it work?** — that's a different question from any single layer, and it applies no matter which layer you're operating in.
- **What it's really about:** every skill in AI-assisted development sits at one of these four levels. Layer 1 drives the model. Layer 2 shapes what it can see. Layer 3 enforces the rules of the system. Layer 4 keeps the whole thing running without you.
- **Why this helps you:** once you can place a technique on this map, you know what it's actually doing and where its limits are. Feeding it better information? That's Layer 2 — this course. Setting up rules it can't break? Layer 3. Getting it to run unattended? Layer 4. It also tells you where to look next: if something you're building isn't working, the fix is usually one layer up or down from where you're currently working, not a completely different tool.

## Three Things to Believe Before You Touch the Tools

- Before we get into any command or setting, let's talk about the AI itself. Three ideas, all from Andrej Karpathy (OpenAI co-founder, the person who coined "vibe coding") — and honestly, everything in this course rests on them.

**1. It's a ghost, not a person.**
- Keep the "brief it like a colleague" habit from AI Prompting in 2026 — that part still holds. But drop the personhood.
- Think of it like this: no ego, no motivation, no memory of yesterday. It won't get offended, won't get tired, and won't take initiative you didn't ask for.
- You manage it. It doesn't manage itself. The rules file, plan mode, hooks — all of that is just different ways of managing it.

**2. Its intelligence is jagged.**
- You've already seen a version of this in AI Prompting Concept 12: different models are good at different things. Karpathy's point pushes further.
- Even one single model is jagged within itself — superhuman at one task, surprisingly weak at the next, sometimes in the same minute.
- Simple takeaway: never assume that because it nailed something hard, it'll automatically nail something easy. Check the easy things too.

**3. Trust it exactly as far as the output can be checked.**
- The closer a task is to checkable — the tests pass, the file exists, the numbers add up — the more comfortable you can be handing it over.
- Where the output can't be checked, the judgment call stays with you. No shortcut around that.

- Hold onto that third one especially. It grows into the single most important pattern in this course — the verification loop, Concept 10 — and from there into two entire courses of their own: **Spec-Driven Development** teaches you to write the check, and **Loop Engineering** teaches you to run it without you standing over it.

## Two Tools, One Set of Skills

- This course walks through two tools side by side: **Claude Code** (built by Anthropic) and **OpenCode** (open-source, works with any AI model).
- Why bother with both? Because if a technique works in both tools, it's a real skill, not a tool-specific trick. What you learn here carries over from one to the other.

| | Claude Code | OpenCode |
|---|---|---|
| Made by | Anthropic | Open-source community |
| AI models | Claude only | Claude, GPT, Gemini, DeepSeek, local models |
| Best for | Best Claude performance out of the box | Flexibility, cost control, free models |
| Price | Subscription or API | Free models available, or bring your own API key |

- Pick whichever fits your situation — everything in this course works the same way in both.
- One heads-up: this is **current as of July 2026**, and both tools update often. Before any session, run `claude update` or `opencode upgrade` to make sure you're not working off a stale version. If you haven't installed either one yet, that's covered in Section 1 below.
