**Walking through the execution:**

- Execution starts in `main()`, running statement 1, then statement 2.
- Statement 3 is a **function call** — control jumps into `fun()`.
- Inside `fun()`, statements 1, 2, and 3 run in order.
- Once `fun()` finishes, control **returns** to the exact line in `main()` where it was called (line 3).
- If that line has any leftover work — for example, `fun(x) * 2`, where the result of `fun(x)` must be multiplied by `2` — that leftover work happens **only after** the function has returned a value.
- After that, execution continues with line 4, then line 5.

**Example:** if `fun(x)` returns `10`, and the calling line was `fun(x) * 2`, the multiplication (`10 * 2`) can only happen *after* `fun()` has actually returned — not before.

<span style={{ color: "#2563eb", fontWeight: 700 }}>This is the single most important idea to carry into recursion: a function call pauses the calling line until the called function completely finishes, and only then does any remaining work on that line get done.</span>

## What Is Recursion?

> A recursive function is a function that calls itself.

```c
Type fun(param)
{
    if (<base condition>)
    {
        1: ____
        2: fun(param);
        3: ____
    }
}
```

Two essential ingredients:

- **The function calls itself** (line 2 above, calling `fun(param)` again).
- **A base condition** — some condition that eventually stops the recursive calls.

**Why is the base condition essential?** Without one, the function would keep calling itself endlessly — infinite recursion. At some point, the condition must become false, so the function stops calling itself and simply returns.

## A First Example

```c
void fun1(int n)
{
    if (n > 0)
    {
        1: printf("%d", n);
        2: fun1(n - 1);
    }
}

void main()
{
    int x = 3;
    fun1(x);
}
```

Inside the function, two steps run whenever `n > 0`:

1. **Print** `n`.
2. **Call itself** with `n - 1`.

**Question:** if we call `fun1(3)`, what happens?

**Tracing in words:** `fun1(3)` prints `3`, then calls `fun1(2)`, which prints `2`, then calls `fun1(1)`, which prints `1`, then calls `fun1(0)` — the base case, which does nothing and returns immediately. **Final output: `3 2 1`**

## Comparing Two Versions: Order Matters

Now compare `fun1` with a second function, `fun2`, where the **order of the two steps is swapped**:

```c
void fun1(int n)          void fun2(int n)
{                          {
    if (n > 0)                 if (n > 0)
    {                          {
        1: printf("%d", n);        1: fun2(n - 1);
        2: fun1(n - 1);            2: printf("%d", n);
    }                          }
}                          }
```

- `fun1`: **print, then call.**
- `fun2`: **call, then print.**

Here is the same tracing tree idea applied to `fun2` — this time, nothing is printed on the way down; each print only happens on the way back up, right as that level is about to return.

## Ascending and Descending Phases

This gives us proper names for the two phases:

```c
void fun(int n)
{
    if (n > 0)
    {
        Ascending  1: Calling
                   2: fun(n - 1) * 2;
        Descending 3: Returning
    }
}
```

- **Ascending phase:** everything that happens **before** the recursive call — this runs on the way *in*, as the recursion goes deeper and deeper. (The blue arrows in the diagrams above.)
- **Descending phase:** everything that happens **after** the recursive call — this runs on the way *back out*, as each call finishes and returns to the one that called it. (The orange arrows above.)

**General rule:** in a recursive function, anything written **before** the recursive call executes during the ascending phase (at calling time). Anything written **after** the recursive call — including any leftover computation, such as multiplying the returned result by `2` — executes during the descending phase (at returning time).

## Recursion vs. Loops

Both loops and recursion **repeat** something — so what's the actual difference?

- A **loop** only has one phase: it repeats an action, moving forward, with nothing happening "on the way back."
- **Recursion** has **two** phases: the ascending phase (going in) and the descending phase (coming back out).

<span style={{ color: "#2563eb", fontWeight: 700 }}>This descending phase is the real power of recursion.</span> It gives you a natural way to do work *after* a smaller version of the problem has already been solved and has returned — something a plain loop cannot easily express on its own. This is exactly why recursion becomes so useful for problems like backtracking, divide and conquer, and dynamic programming, where "do something after the smaller sub-problem comes back" is a core part of the approach.

---

## Summary

- A recursive function **calls itself**, and must have a **base condition** to eventually stop.
- Recursive functions are understood by **tracing them as a tree** of calls.
- The **order of statements matters**: what's written before the recursive call runs during the **ascending** (calling) phase; what's written after runs during the **descending** (returning) phase.
- Recursion has two phases where a loop only has one — this is recursion's core strength, enabling patterns like backtracking, divide and conquer, and dynamic programming.
