## Lists and Indexing/Slicing

Lists are Python's core data structure for holding ordered collections — and Blind 75 array problems are basically all about manipulating lists.

```python
nums = [10, 20, 30, 40, 50]
```

**Indexing** — accessing a single element by position (starts at **0**, not 1):

```python
nums[0]    # 10  (first element)
nums[2]    # 30  (third element)
nums[-1]   # 50  (last element — negative counts from the end)
nums[-2]   # 40  (second-to-last)
```

**Slicing** — grabbing a sub-section using `list[start:stop]`:

```python
nums[1:3]    # [20, 30]        — starts at index 1, stops BEFORE index 3
nums[:2]     # [10, 20]        — from the beginning up to (not including) index 2
nums[2:]     # [30, 40, 50]    — from index 2 to the end
nums[:]      # [10, 20, 30, 40, 50]  — a full copy of the list
nums[::-1]   # [50, 40, 30, 20, 10]  — reversed (step of -1)
```

<span style={{ color: "#dc2626", fontWeight: 700 }}>Same off-by-one trap as `range()`: the `stop` index is never included.</span> <span style={{ color: "#2563eb", fontWeight: 700 }}>`nums[::-1]` reverses the list — a step of `-1` walks it back to front</span>, no loop required.

**Common list operations you'll use constantly:**

```python
nums.append(60)      # add to the end       -> [10,20,30,40,50,60]
nums.pop()            # remove & return last -> 60, list shrinks back
nums.pop(0)           # remove & return index 0
len(nums)             # length of the list -> 5
30 in nums            # membership check -> True
nums.sort()           # sort in place
sorted(nums)          # returns a NEW sorted list, leaves nums unchanged
```

<span style={{ color: "#2563eb", fontWeight: 700 }}>`nums.sort()` sorts in place</span> — it mutates `nums` itself and returns `None`. `sorted(nums)` leaves `nums` untouched and hands back a new sorted list instead.

**Modifying while looping — a real trap:**

```python
for i in range(len(nums)):
    nums[i] = nums[i] * 2   # fine — modifying by index
```

<span style={{ color: "#dc2626", fontWeight: 700 }}>But don't change a list's *size* (append/remove) while iterating over it directly with `for x in nums:` — it skips elements or errors, because the sequence shifts under you mid-loop.</span> Worth slowing down on — a concrete walkthrough beats just stating the rule.

**Why changing values by index is safe**

- `range(len(nums))` is calculated **once**, at the start. Since `len(nums)` is `3`, this becomes `range(3)` → the fixed sequence `0, 1, 2`.
- The loop just walks through `0, 1, 2` no matter what you do to `nums` inside.
- On each pass, you use `i` as an address ("go to slot `i`") and overwrite whatever value is sitting there.
- You're not touching how many slots exist — just what's written into each slot.

```python
nums = [1, 2, 3]
for i in range(len(nums)):
    nums[i] = nums[i] * 2
```

Step by step:
```
i=0: nums[0] = nums[0]*2 = 2   → nums is now [2, 2, 3]
i=1: nums[1] = nums[1]*2 = 4   → nums is now [2, 4, 3]
i=2: nums[2] = nums[2]*2 = 6   → nums is now [2, 4, 6]
```

<span style={{ color: "#16a34a", fontWeight: 700 }}>Safe, predictable — the loop never cared about the list's length changing, because it isn't changing.</span>

**Why changing the list's size while looping breaks things**

```python
nums = [1, 2, 3, 4]
for x in nums:
    if x % 2 == 0:
        nums.remove(x)
```

Here, `for x in nums:` doesn't loop over a fixed count like `range()` did — it walks through the list **live**, using an internal position counter (think of it as "look at position 0, then position 1, then position 2...").

Walk through it:
```
position 0: x = 1 (odd, skip)
position 1: x = 2 (even) → nums.remove(2) → list is now [1, 3, 4]
```

<span style={{ color: "#dc2626", fontWeight: 700 }}>Here's the problem: after removing `2`, everything after it shifts left by one.</span> `4` used to be at position 3, now it's at position 2. But the loop's internal counter has already moved on to position 2 next:

```
position 2: x = 4 (even) → nums.remove(4) → list is now [1, 3]
position 3: doesn't exist → loop ends
```

<span style={{ color: "#dc2626", fontWeight: 700 }}>Notice: `3` was never checked! It got shifted into position 1, but the loop had already passed position 1 by the time that happened. You silently skipped an element — no error, just a wrong answer, which is the worst kind of bug.</span>

**The fix, if you need to remove things:**

```python
nums = [1, 2, 3, 4]
nums = [x for x in nums if x % 2 != 0]   # build a NEW list instead
```

<span style={{ color: "#2563eb", fontWeight: 700 }}>**The rule of thumb:** looping by index (`range(len(nums))`) to *overwrite values* = safe. Looping directly over the list (`for x in nums`) while *adding/removing elements* = dangerous, because the list is shifting under the loop's feet while it's still walking through it.</span>

**Two-pointer pattern (you'll see this everywhere in Blind 75):**

```python
left, right = 0, len(nums) - 1
while left < right:
    # do something with nums[left] and nums[right]
    left += 1
    right -= 1
```

<span style={{ color: "#2563eb", fontWeight: 700 }}>This pattern shows up throughout Blind 75 — pair sums, palindrome checks, reversing in place, and container/area problems all lean on two pointers moving toward each other.</span>

## What Does "In Place" Actually Mean?

Good question — "in place" is a term you'll see constantly in these problems, so worth pausing on.

<span style={{ color: "#2563eb", fontWeight: 700 }}>**"In place" means the operation modifies the original object directly in memory, rather than creating a new one and returning it.**</span>

```python
nums = [30, 10, 20]
nums.sort()
print(nums)   # [10, 20, 30]  — the ORIGINAL list itself changed
```

Notice: `nums.sort()` doesn't `return` anything useful — if you tried `x = nums.sort()`, `x` would be `None`. <span style={{ color: "#16a34a", fontWeight: 700 }}>That's your clue it's an in-place method: it changes `nums` directly and gives nothing back.</span>

Compare that to `sorted()`, which is **not** in place:

```python
nums = [30, 10, 20]
new_list = sorted(nums)
print(nums)       # [30, 10, 20]  — original UNCHANGED
print(new_list)   # [10, 20, 30]  — a brand new list
```

<span style={{ color: "#dc2626", fontWeight: 700 }}>**Why this matters for LeetCode:** many problems explicitly ask you to modify the array "in place" to save memory — meaning don't create a second array, just rearrange the values inside the one you were given.</span> This shows up a lot (e.g. "Remove Duplicates from Sorted Array," "Move Zeroes").

A simple way to think about it:
- `nums.sort()` → same list, reordered, returns `None`
- `sorted(nums)` → new list, `nums` untouched, returns the new list

Same pattern applies to other methods: `.append()`, `.pop()`, `.reverse()` are in-place (change the list directly, return `None` or the removed item). `.reverse()` vs `nums[::-1]` is the same distinction — the first mutates, the second creates a new reversed list.
