# Contains Duplicate

**LeetCode #217 · 🟢 Easy**

*Blind 75 Problem 3 of 75 · Array · Problem 3 of 10*

---

### Problem Statement

> Given an integer array `nums`, return `True` if any value appears **more than once** in the array, otherwise return `False`.

```python
# Example 1
Input: nums = [1, 2, 3, 3]
Output: True

# Example 2
Input: nums = [1, 2, 3, 4]
Output: False
```

**Constraints:**
- `1 <= nums.length <= 10⁵`
- `-10⁹ <= nums[i] <= 10⁹`

---

### Hint

Checking every number against every other number works, but it's slow. What data structure gives you an **instant** "have I seen this before?" check, instead of rescanning the list each time?

### Complete Walkthrough

#### <span style={{ color: "#dc2626", fontWeight: 700 }}>Brute Force Approach</span>

The most basic way to solve this: **compare every number to every other number** in the list and check if any two match.

```python
def containsDuplicate(nums):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] == nums[j]:
                return True
    return False
```

**Breaking it down:**
- `n = len(nums)` — store the length of the list once, so we don't recalculate it repeatedly.
- `for i in range(n):` — the **outer loop**, walking through every index: `0, 1, 2, 3...`
- `for j in range(i + 1, n):` — the **inner loop**, walking through every index **after** `i`. Starting at `i + 1` avoids comparing a number to itself, and avoids re-checking pairs already checked.
- `if nums[i] == nums[j]:` — compares the actual values at those two positions.
- `return True` — the moment a match is found, stop immediately and report it.
- `return False` — if both loops finish with no match found, every number was unique.

**Trace it**, using `nums = [1, 2, 3, 3]`:

```
i=0 (nums[0]=1):
    j=1 (nums[1]=2): 1 == 2? No
    j=2 (nums[2]=3): 1 == 3? No
    j=3 (nums[3]=3): 1 == 3? No
i=1 (nums[1]=2):
    j=2 (nums[2]=3): 2 == 3? No
    j=3 (nums[3]=3): 2 == 3? No
i=2 (nums[2]=3):
    j=3 (nums[3]=3): 3 == 3? YES → return True
```

**Time Complexity: O(n²)** — for every number, we rescan a large chunk of the rest of the list, so with `n` numbers this does roughly `n × n` comparisons in the worst case.

**Space Complexity: O(1)** — just a couple of loop variables, no extra data structures.

**Why it fails:** fine for small lists, but with `n` up to `10⁵`, `O(n²)` becomes roughly `10¹⁰` comparisons in the worst case — far too slow to pass within a reasonable time limit.

---

#### Intuition

Instead of asking "does this number match anything **else** in the list?" by rescanning, ask a cheaper question: "have I already **seen** this number?" — and answer it instantly using a **hash set**.

A **set** is similar to a dictionary, except it stores only **values**, no keys. Its purpose here: keep track of every unique number seen so far, and instantly check whether a new number has already been seen — the same `in` check that makes dictionary key lookups `O(1)`.

---

#### <span style={{ color: "#16a34a", fontWeight: 700 }}>Optimized Approach — Hash Set</span>

```python
def containsDuplicate(nums):
    seen = set()
    for n in nums:
        if n in seen:
            return True
        seen.add(n)
    return False
```

**Breaking it down:**
- `seen = set()` — creates an empty set, like an empty box for numbers already encountered.
- `for n in nums:` — walk through the list **once**, value by value.
- `if n in seen:` — checks whether this number is already inside the set, in **O(1)**, constant time — same reasoning as checking `"key" in dictionary`.
- `return True` — if it's already in the set, a duplicate was found. Stop immediately.
- `seen.add(n)` — if it wasn't a duplicate, add it to the set so future numbers can be compared against it.
- `return False` — if the loop finishes with no matches, there were no duplicates.

**Trace it**, using the same `nums = [1, 2, 3, 3]`:

```
seen = {} (empty)

n=1: is 1 in seen? No  → add it → seen = {1}
n=2: is 2 in seen? No  → add it → seen = {1, 2}
n=3: is 3 in seen? No  → add it → seen = {1, 2, 3}
n=3: is 3 in seen? YES → return True
```

Only **one loop** this time, and it stops the instant a repeat is found.

**Why this is fast:** the list is walked through only **once** — **O(n) time** — and each `in seen` check is instant, instead of rescanning the rest of the list every time like brute force did.

**Trade-off:** this version uses extra memory — the `seen` set can grow to hold up to `n` numbers in the worst case, so it uses **O(n) space**. This is the classic **time vs. space trade-off**: brute force saved memory but was slow; this version trades a bit of memory for much greater speed.

---

### Complexity Analysis

| Approach | Time | Space |
|---|---|---|
| Brute force (nested loops) | O(n²) | O(1) |
| Hash set | O(n) | O(n) |

---

### Edge Cases

**Universal checklist:**
- **Empty array:** not possible here since `nums.length >= 1`, but a single-element array (`nums = [5]`) should return `False` — nothing to compare it to.
- **All identical values:** `nums = [7, 7, 7, 7]` → returns `True` on the second element.
- **Already sorted / reverse sorted:** neither approach cares about order — both scan every element regardless.
- **Negative numbers:** `nums = [-1, -1, 2]` → the hash set treats `-1` like any other value; no special-casing needed.
- **Largest allowed values:** `nums = [10⁹, -10⁹]` → both fit comfortably as Python `int`s and hash normally.

**Section-Specific Edge Cases:**
- **Duplicate at the very last position:** `nums = [1, 2, 3, 4, 1]` — the hash set approach still catches it correctly since `seen` accumulates every value walked past, no matter how far apart the duplicate pair sits.
- **Duplicate right at the start:** `nums = [9, 9, 1, 2]` — returns `True` immediately on the second element, which is exactly why the hash set version can be faster in practice than its worst-case `O(n)` suggests — early exits are common.

> **Simple rule:** whenever a problem asks "has this been seen before?", reach for a hash set before reaching for nested loops — trading `O(n)` space for a drop from `O(n²)` to `O(n)` time is almost always worth it.

---

### Key Takeaway

> Whenever you need to know "has this been seen before?", a hash set turns an `O(n²)` rescan into an `O(n)` single pass — one loop, one `in` check, one `add`.

---

### Real-World Application

Deduplication checks that run constantly in production — a login system checking whether a username already exists, an e-commerce cart checking whether an item was already added, or an analytics pipeline dropping duplicate event IDs before counting. All of these ask the exact same question this problem asks: "have I seen this value before?" — and all of them reach for the same answer, a hash set (or hash-backed index), for the same reason: instant lookups instead of rescanning everything already processed.
