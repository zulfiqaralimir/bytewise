### Problem Statement

> You are given an integer array `height` of length `n`. There are `n` vertical lines drawn such that the two endpoints of line `i` are `(i, 0)` and `(i, height[i])`. Find two lines that together with the x-axis form a container that holds the most water. Return the maximum amount of water a container can store.

You cannot slant the container — the two lines you pick must stay vertical, so the water level is capped by whichever of the two lines is **shorter**.

```python
# Example
Input: height = [1,7,2,5,4,7,3,6]
Output: 36
# Bars at indices 1 and 7 have heights 7 and 6.
# width = 7 - 1 = 6, height = min(7,6) = 6, area = 36
```

### Complete Walkthrough

#### The Formula

This problem asks for the "amount of water," which in real life would mean **volume** (`length × width × height`). But the chart here is entirely 2D — there's no depth dimension given anywhere.

What the problem is actually calculating is the **cross-sectional area** — imagine slicing the container down the middle and looking at that flat side-view slice. That's a 2D rectangle:

```python
area = width × height
```

The problem implicitly assumes every possible container shares the same fixed depth (say, 1 unit). Since that depth is identical no matter which two lines you pick, comparing volumes and comparing areas give the exact same ranking — the depth is a constant that never changes which pair wins. So the problem simplifies to comparing area directly.

```python
water = min(height[i], height[j]) × (j - i)
```

Two parts:
- **Height** — the shorter of the two lines. Water spills over the shorter side, so it can never rise higher than that.
- **Width** — the distance between the two lines, `j - i`.

**Checking it on the example** — indices `1` (height `7`) and `7` (height `6`):

```python
water = min(7, 6) × (7 - 1) = 6 × 6 = 36
```

Matches the expected output.

---

#### <span style={{ color: "#dc2626", fontWeight: 700 }}>Brute Force Approach</span>

Check every possible pair of lines, calculate the area for each, and keep track of the biggest one found.

```python
def maxArea(height):
    n = len(height)
    best = 0
    for i in range(n):
        for j in range(i + 1, n):
            area = min(height[i], height[j]) * (j - i)
            best = max(best, area)
    return best
```

**Breaking it down:**
- `for i in range(n):` and `for j in range(i + 1, n):` — check every pair of positions without repeating any pair twice.
- `area = min(height[i], height[j]) * (j - i)` — apply the formula.
- `best = max(best, area)` — keep the largest area seen so far.

**Trace it**, using `height = [1,7,2,5,4,7,3,6]` — a few key pairs:

```
i=1 (h=7), j=5 (h=7): area = min(7,7) * (5-1) = 7*4 = 28
i=1 (h=7), j=7 (h=6): area = min(7,6) * (7-1) = 6*6 = 36  ← best
i=5 (h=7), j=7 (h=6): area = min(7,6) * (7-5) = 6*2 = 12
```

Checking all pairs, the maximum found is `36`, using indices `1` and `7` — matching the expected output.

**Time Complexity: O(n²)** — checking every pair means roughly `n × n` combinations.

**Space Complexity: O(1)** — just a few tracking variables, no extra data structures.

**Why it fails:** correct, but with `n` up to `100,000`, `n²` is far too slow. The real challenge is finding a way to skip most pairs without ever computing their area.

---

#### Intuition

Start with two pointers at the far ends — the widest possible container. At each step, **move the pointer at the shorter line inward** — because that shorter line is the limiting factor, and moving the taller one could never help (width only shrinks, while height stays capped by the same short wall).

---

#### <span style={{ color: "#16a34a", fontWeight: 700 }}>Optimized Approach — Two Pointers</span>

```python
def maxArea(height):
    left, right = 0, len(height) - 1
    best = 0
    while left < right:
        area = min(height[left], height[right]) * (right - left)
        best = max(best, area)
        if height[left] < height[right]:
            left += 1
        else:
            right -= 1
    return best
```

**Breaking it down:**
- `left, right = 0, len(height) - 1` — two pointers starting at opposite ends.
- `while left < right:` — continue until the pointers meet.
- `area = min(height[left], height[right]) * (right - left)` — the same formula, applied at the current pointer positions.
- `if height[left] < height[right]:` — move the pointer standing at the **shorter** line inward.
- Otherwise, move `right` inward.

**Trace it**, using `height = [1,7,2,5,4,7,3,6]`:

```
left=0, right=7, best=0

height[0]=1, height[7]=6: area = min(1,6)*(7-0) = 1*7 = 7        → best=7
  height[left]=1 < height[right]=6 → move left → left=1

height[1]=7, height[7]=6: area = min(7,6)*(7-1) = 6*6 = 36       → best=36
  height[left]=7 >= height[right]=6 → move right → right=6

height[1]=7, height[6]=3: area = min(7,3)*(6-1) = 3*5 = 15       → best=36
  height[left]=7 >= height[right]=3 → move right → right=5

height[1]=7, height[5]=7: area = min(7,7)*(5-1) = 7*4 = 28       → best=36
  height[left]=7 >= height[right]=7 → move right → right=4

height[1]=7, height[4]=4: area = min(7,4)*(4-1) = 4*3 = 12       → best=36
  height[left]=7 >= height[right]=4 → move right → right=3

height[1]=7, height[3]=5: area = min(7,5)*(3-1) = 5*2 = 10       → best=36
  height[left]=7 >= height[right]=5 → move right → right=2

height[1]=7, height[2]=2: area = min(7,2)*(2-1) = 2*1 = 2        → best=36
  height[left]=7 >= height[right]=2 → move right → right=1

left(1) < right(1)? No → loop ends
```

**Final result:** `best = 36` — matches, found in 7 steps instead of checking all 28 possible pairs.

**Why moving the shorter side is safe:** say `height[left]` is the shorter line. If `left` stayed fixed and only `right` moved inward, the width would only shrink, while the height stays capped by `height[left]` regardless — still the limiting wall. So no container using this same `left` paired with anything further from `right` could ever beat what's already been calculated. It's only by moving `left` itself that a taller wall (and possibly a better answer) could be found. That's what makes it safe to move the shorter pointer and never miss the true best answer.

### Complexity Analysis

| Approach | Time | Space |
|---|---|---|
| Brute force, check every pair | O(n²) | O(1) |
| Two pointers | O(n) | O(1) |

### Edge Cases

**Universal checklist:**
- **Minimum size array:** `height = [1,1]` → only one possible pair; `left` and `right` meet immediately after computing its area.
- **All identical values:** `height = [4,4,4,4]` → every pair has `h = 4`; the widest pair (first and last) always wins, since width is what varies.
- **Already sorted / reverse sorted:** `height = [1,2,3,4,5]` or its reverse → the algorithm still works, since it never relies on the array being unsorted.
- **Zero height:** `height = [0,3,0,5]` → a line of height `0` can never be the limiting wall in a *winning* pair (area would be `0`), so the pointer sitting on it always advances immediately.
- **Answer uses the very first and last elements:** `height = [9,1,1,1,9]` → the initial widest pair is also the best one; `best` is set correctly on the very first iteration.

**Section-Specific Edge Cases:**
- **Tie in height at `left` and `right`:** the code moves `right` (the `else` branch) when heights are equal — either pointer would be safe to move here, since both walls are equally short.
- **A tall wall trapped between two short ones:** `height = [8,1,1,1,1,1,8]` → the middle values never matter; both pointers race past them, since neither can beat the outer pair's height cap without also losing width.
- **Descending-then-ascending shape:** `height = [5,4,3,2,3,4,5]` → confirms the two-pointer approach doesn't get fooled by a "valley" shape; it still finds the outer pair `(5,5)` as the best width-6 option to compare against.

> **Simple rule:** whenever an answer is defined by `min(a, b) × distance`, and moving toward a wider pair can only hurt one side of that formula, check whether provably discarding the "obviously worse" pointer move turns an `O(n²)` all-pairs scan into an `O(n)` two-pointer sweep.

---

### Key Takeaway

> Start at maximum width and only ever move the shorter wall — moving the taller wall can never increase the area, since it can only shrink the width while the limiting height stays the same or gets worse. That one-directional guarantee is what makes the greedy two-pointer sweep correct, not just fast.

---

### Real-World Application

Reservoir and tank capacity planning: given a row of support pillars or dam walls at fixed positions with fixed heights, engineers use the same shrink-from-both-ends logic to quickly identify which pair of walls could hold the most volume between them, without testing every possible pair. The same two-pointer "give up the constrained side" pattern also shows up in histogram-based bandwidth allocation, where you're picking two time slots bounded by the narrower of two capacity limits.

> **Why this algorithm?** The two-pointer sweep is the right choice specifically because moving the taller wall is *provably* never better — that guarantee is what lets the algorithm safely skip most of the O(n²) search space instead of just being a faster heuristic.
